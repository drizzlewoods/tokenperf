## 时间边界

计时使用单调时钟。请求延迟包含 HTTPX 请求构造、连接池、DNS/TLS、网络与客户端解析开销，不是纯服务端推理时间。协议完成表示流式收到 `[DONE]`，或非流式响应体已完整接收；不等待服务器关闭 keep-alive TCP 连接。

首次连接和连接复用可能不同。每个条件先暖机，暖机与测量使用同一个客户端；矩阵也复用客户端。暖机次数较少时不能保证所有并发连接已预热。

每个条件的全部请求视为在正式阶段开始时入队，固定数量的工作者取下一个请求，因此 `queue_seconds` 随等待增长。这是闭环固定并发测试，不是固定请求到达率的开放压测。

总请求超时覆盖等待响应头和完整响应体，流式数据持续到达不会无限延长超时。无重试、无自动重定向；默认不读取环境代理设置。

## 文本与 token

首内容仅计入非空文本。拒绝、工具调用和内容过滤不是本版本的成功文本结果。`stop` 与 `length` 为正常完成，空文本、格式错误、缺少终止标记或连接异常归为失败。流式要求有效文本完成事件和 `[DONE]`；某些宽松兼容服务缺少结束标记，会被归为协议错误。

数据块可能包含多个 token，因此本版本不会将块间隔称为 ITL，也不能从首块时间和总 token 数还原精确生成阶段 token/s。`generation_tokens_per_second` 预留为空，不伪造精度。

`output_tokens_per_second` 为端到端输出 token 吞吐：可信文本 completion tokens / 完整请求延迟，包含首内容等待时间。只有 usage 明确排除隐藏推理和其他非文本 token 时才计算。服务未提供 token 明细时保留 usage 的总数，但该速率为空。这比通常的“生成阶段 tokens/s”更保守，二者不能混用。

不根据字符数或本地假定 tokenizer 补算 tokens。单 token 响应仍可记录 usage，不推算逐 token 间隔。

## 汇总

成功率以已完成正式样本为分母。取消运行的样本数可能小于配置请求数，必须结合运行状态解读。失败样本消耗的时间计入测量窗口，失败延迟单独汇总。

分位数采用排序后线性插值；空样本为空值。少量样本的 P95/P99 不代表稳定的尾延迟分布。

端到端吞吐使用条件测量墙钟时间，不能把并行请求各自时长相加作为分母。暖机单独存储，不计入分位数、错误率或吞吐。

本工具不推断服务器硬件能力，不消除公网延迟和客户端事件循环调度开销，不保证供应商提供的 usage 正确。
